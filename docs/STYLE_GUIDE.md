## Overview

This style guide establishes consistent writing, formatting, and quality standards for all content produced by the multi-agent workflow system. Designed to be niche-agnostic, this guide can be adapted to any of the three proposed niches once Abbey selects the primary focus.

## Core Principles

### 1. Clarity Over Cleverness
- Priority: Make complex topics understandable
- Avoid: Jargon without explanation, overly complex sentences
- Use: Simple language, clear structure, practical examples

### 2. Actionability
- Every piece must provide concrete value
- Include: Step-by-step instructions, code samples, templates
- Avoid: Theoretical discussions without practical application

### 3. Consistency
- Voice: Professional yet approachable
- Tone: Helpful, not condescending
- Style: Follow this guide for all content

### 4. Accuracy
- Fact-check: All technical claims must be verifiable
- Sources: Cite authoritative references
- Testing: Code samples must be tested and working

## Writing Style

### Voice and Tone
- Voice: Knowledgeable peer, not a teacher or salesperson
- Tone: Conversational but professional
- Avoid: Marketing fluff, excessive hype, fear-mongering

### Sentence Structure
- Length: 15-25 words maximum
- Complexity: One idea per sentence
- Paragraphs: 2-4 sentences each
- Avoid: Run-on sentences, passive voice

## Formatting Standards

### Headers
Use sequentially H1 to H2 to H3 to H4. H1 reserved for document title only. H2 for major sections, H3 for subsections, H4 for detailed topics.

### Lists
- Bullet points: Use for unordered items
- Numbered: Use for sequential steps or rankings
- Format: Start with capital letter, end without period (unless complete sentence)
- Nested: Indent with 2 spaces

### Code Formatting
- Inline: Use backticks for commands, file names, code references
- Blocks: Use triple backticks with language specifier
- Line length: 80 characters maximum for code blocks
- Syntax highlighting: Always specify language

### Links
- Format: Use descriptive text, not raw URLs
- External links: Open in new tab
- Internal links: Use relative paths

## Content Structure Templates

### Article Template
Section with executive summary, introduction, main content, conclusion, resources

### Tutorial Template
Section with prerequisites, steps, troubleshooting, final notes

### Comparison Template
Section with overview, comparison matrix, detailed analysis, recommendation

## Grammar and Mechanics

### Capitalization
- Titles: Sentence case
- Headers: Sentence case
- Acronyms: ALL CAPS
- Proper nouns: Capitalize

### Punctuation
- Commas: Use Oxford comma
- Quotes: Use double quotes
- Dashes: Use em dash without spaces
- Apostrophes: Use smart apostrophes

### Numbers
- Zero to nine: Spell out
- 10 and above: Use numerals
- Exceptions: Measurements, code, statistics, ranges

### Dates and Times
- Dates: YYYY-MM-DD format
- Times: 24-hour format with timezone
- Time ranges: Use en dash
- Durations: Use abbreviations

## File Naming Conventions

### Documents
- Format: lowercase-with-hyphens.md
- Examples: project-brief.md, style-guide.md

### Images
- Format: lowercase-with-hyphens.ext
- Prefix: Use descriptive prefix

### Code Files
- Follow language conventions

## Niche-Specific Adaptations

### For AI Agent Development
- Technical depth: High
- Code samples: Required
- Architecture diagrams: Use Mermaid
- Terminology: Define in glossary

### For Open-Source Business Models
- Case studies: Include real-world examples
- Financial terms: Explain clearly
- Legal considerations: Note licensing
- Community focus: Highlight collaboration

### For Developer Productivity
- Practical focus: Every article must include actionable advice
- Tool comparisons: Use comparison templates
- Workflow diagrams: Show before/after
- Metrics: Include productivity measurements

## Quality Checklist

### Content Quality
- Title is clear and specific
- Introduction explains what and why
- Each section has a clear purpose
- Examples are practical and working
- Conclusions summarize key points

### Technical Accuracy
- All code samples are tested
- All claims are verifiable
- Sources are cited
- Links are working
- Terminology is correct

### Formatting
- Headers follow hierarchy
- Lists are properly formatted
- Code blocks have language specified
- Images have alt text
- No spelling or grammar errors

### Style
- Voice is consistent
- Tone is appropriate
- Sentences are clear and concise
- Active voice is used
- No jargon without explanation
